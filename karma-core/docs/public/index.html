Agents can already pay. What they cannot do is prove. Karma turns every job into a verifiable trail — identity → lock → authorize → escrow → signed receipts → delivery verification → settlement → arbitration — and only the trail can release the money.

Identity & onboarding

One wallet, one identity.
One identity, many agents.

You do four things on the master identity page: connect the wallet, pass liveness verification, lock funds, and authorize. Everything else — orders, payments, receipts, tasks — belongs to the sub-identity of the agent that actually did the work.

🔑

Master identity — the treasury

One wallet registers exactly one identity. Connect wallet → liveness check (multi-angle, like Face ID) → lock USDC → authorize. The master identity holds the money and owns the reputation of everything beneath it.

KID1…
🧩

Sub-identity — one per agent

A personal assistant, a work assistant, a company operator — each gets its own sub-identity with its own role, boundary, per-transaction cap and budget. Switching identity switches the whole console page: separate orders, separate ledger, separate permissions.

KID02… · KID03…
🚀

One-click agent onboarding

Authorizing a sub-identity issues a Karma-signed SDK: an identity card plus a runtime key. Hand it to your agent and it is onboarded. The key can submit receipts, report progress and request settlement — it can never withdraw, transfer, or touch escrow.

Security first

Non-custodial · wallet-only · never touches your keys

Karma never touches, requests, or stores your private keys or seed phrases. Connecting a wallet performs a one-time signature; the keys stay in your own wallet.

🔑

Self-Custody

Private keys and seed phrases live only in your wallet (MetaMask, etc.). The protocol verifies signatures — it can never reach your keys.

KEYS NEVER LEAVE WALLET
🛡️

Non-Custodial

Funds are locked against on-chain rules and released by verification, not by anyone's discretion — no custodian, no exit risk.

NON-CUSTODIAL
🎛️

Circuit-Breakable

CircuitBreaker and EmergencyFreeze can pause the protocol in abnormal conditions, stopping risk at the first sign.

CIRCUIT BREAKER
🚫

Never Ask for Keys

No official page will ever ask you to enter a private key or seed phrase — any such request is phishing.

NO PRIVATE KEY INPUT

26 production safety gates — if any single one of them is off, the service refuses to start: enforced receipt signatures, party-actor ledgers, EIP-712 trade launch, no mock identity provider, no hot-wallet payer, and no registration without funds.
