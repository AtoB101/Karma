## 1) Bill Token 状态机

```mermaid
stateDiagram-v2
  [*] --> MINTED: lock(USDC)
  MINTED --> BOUND: bind / bindWithIntent / bindWithAttestation
  MINTED --> BURNED: unlock（未绑定退回）
  BOUND --> BURNED: settle 完成 / refund / dispute resolve
  BURNED --> [*]

  note right of MINTED
    1:1 对应锁定 USDC
    supply == locked
  end note
```

## 2) Binding 状态机

```mermaid
stateDiagram-v2
  [*] --> ACTIVE: bind 成功
  ACTIVE --> PENDING: 批量阈值（可选）
  PENDING --> ACTIVE: 继续
  ACTIVE --> FINALIZING: settle(proofHash)
  FINALIZING --> SETTLED: finalizeSettle
  FINALIZING --> DISPUTED: dispute
  DISPUTED --> SETTLED: resolveDispute
  ACTIVE --> REFUNDED: refundOnTimeout
  FINALIZING --> REFUNDED: 超时退款路径
  SETTLED --> [*]
  REFUNDED --> [*]
```

## 3) 乐观结算主路径（Happy Path）

```mermaid
sequenceDiagram
  participant B as Buyer
  participant A as Agent
  participant C as KarmaBilateral
  participant API as Public API / Evidence

  B->>C: lock(USDC) → buyerBill
  A->>C: lock(USDC) → agentBill
  B->>C: bind(buyerBill, agentBill, scopeHash)
  A->>API: 提交 receipt / evidence bundle
  API-->>B: proofHash / 可验收状态
  B->>C: settle(bindingId, proofHash)
  Note over C: Binding = FINALIZING<br/>争议窗计时
  Note over B,A: 窗内无争议
  B->>C: finalizeSettle(bindingId)
  C-->>B: 释放 buyer 侧 USDC
  C-->>A: 释放 agent 侧 USDC
  Note over C: Bills BURNED · SETTLED
```

## 4) 争议与裁决流

```mermaid
flowchart TD
  S[settle → FINALIZING] --> W{争议窗内?}
  W -->|Buyer dispute| D[DISPUTED]
  D --> E[双方证据 / 自动仲裁规则]
  E --> R[Admin resolveDispute buyerShareBps]
  R --> OUT[按 BPS 分账 · SETTLED]
  W -->|超时无争议| F[finalizeSettle]
  F --> OK[SETTLED 全额按绑定释放]
  BIND[ACTIVE 长期未 settle] --> RF[refundOnTimeout]
  RF --> BACK[各自取回锁定]
```

## 5) 证明层级（已实现 vs 预留）

| 层级 | 方法 | 状态 |
