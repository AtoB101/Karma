# 01 · 问题与方案

## 问题：Agent 经济缺「可强制的信任层」

当两个 AI Agent（或 Agent ↔ 人类买家）要完成一笔有偿任务时，常见失败模式：

1. **对方跑路 / 拒付**：交付了不结算，或收了钱不交付  
2. **中心化托管**：平台扣款权过大，Agent 生态难以去中心化协作  
3. **纯链上逐笔结算**：高频协作 gas 与摩擦过高  
4. **只有支付没有证据**：无法把「交付事实」接到放款条件

白皮书（`docs/whitepaper.md`）将 Karma 定位为：  
**Autonomous AI Agents 的非托管支付 / 结算层** —— 无需信任第三方中介。

## 方案：双边皮肤入局 + 证据驱动放款

```text
双方各锁 USDC（皮肤入局）
        ↓
铸造 Bill Token（1:1 会计凭证，非投机币）
        ↓
bind：冻结交易对 + scopeHash（任务范围）
        ↓
交付 → 证据 Bundle / proofHash
        ↓
settle → 争议窗 → finalizeSettle → 烧 Bill、放 USDC
        ↓
或 dispute / resolve / refundOnTimeout
```

### 设计原则（与路线图一致）

来自 `docs/FOCUS_ROADMAP.md` 的决策矩阵——功能必须至少强化其一：

1. **结算正确性 / 安全**  
2. **Agent 接入摩擦↓**  
3. **证明真实经济完成（USDC 放款）**

否则延后。这保证天使阶段叙事不散：只讲一条轨。

## 差异化（对投资人）

| 维度 | 典型托管平台 | 纯支付协议 (如 x402) | **Karma** |
|------|--------------|----------------------|-----------|
| 资金托管 | 中心化 | 即时支付为主 | **非托管双边锁定** |
| 争议 | 人工客服 | 弱 / 无 | **链上争议窗 + 证据** |
| 与 Agent 栈 | 定制对接 | 支付一跳 | **补 Proof 列，可并立** |
| 会计 | 账本在平台 | 链上转账 | **Bill 守恒不变量** |

## 目标客户（早期）

1. **Agent 运行时 / 编排器**（OpenClaw、OpenManus、自研 Agent）需要可结算的任务合同  
2. **工具 / API 卖方 Agent**：需要预授权、凭证、交付证明后收款  
3. **买家侧 Agent / 人类操作台**：需要锁定预算、验收、争议

## 非目标（避免讲偏）

- 不做通用 DeFi 借贷 / DEX  
- 不把「发协议币」当第一增长故事  
- 不在天使 pitch 里承诺尚未实现的 TEE/ZK/多链
